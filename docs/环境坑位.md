# 环境坑位

> 这份文档记录这个工具在本机真实踩过的每一个坑。格式：**症状 → 根因 → 正确做法**。
> 改代码前先扫一遍，能省掉重复踩坑的时间。编号被代码注释直接引用，**不要重排**。

> 格式：症状 → 根因 → 正确做法

1. **pypdf 在携程火车票 PDF 上直接抛异常** → `More than one /FontFile found`，字体描述符重复 → **主提取器用 PyMuPDF(`fitz`)**，pypdf 只作次选；两者都失败才判"无法解析"。
2. **PDF 版式的增值税电子发票文字是碎片化的**（标签与值分离、竖排单字成行）→ 不能按"标签：值"同行匹配 → 按**全文正则**抽取：20 位连续数字取发票号码、`¥/￥` 后取金额并取最大值（价税合计 ≥ 金额+税额，故最大即价税合计）、`YYYY年MM月DD日` 取开票日期。
3. **铁路电子客票全文里有两个日期**（开票日期 + 乘车日期），且 25 位电子客票号里嵌着 20 位数字 → 日期取**最后一个**匹配；发票号码用 `(?<!\d)(\d{20})(?!\d)` 词边界排除 25 位票号。
4. **同一张发票在邮件里可能带 PDF+XML+OFD 三份**，行程单又是另一个 PDF → 不按"附件"计数，先按**基名分组**，一张发票算一条记录，否则金额会重复计算。
5. **中文关键词走 IMAP 服务器端搜索不可靠**（非 ASCII 与 MIME 编码）→ 采集用**日期窗口**（`SINCE`/`BEFORE`，纯 ASCII）拉取，再用本地规则筛附件，不依赖中文主题搜索。
5b. **QQ IMAP 对带括号的 SEARCH 条件会静默返回整箱邮件** → `"(SINCE \"...\" BEFORE \"...\")"` 实测返回 1093 封（= 全部），不带括号返回 48 封（= 正确窗口）；反转窗口返回 0 证明服务器确实认条件，唯独不认括号。这是"错但不报错"的坑，会把整个邮箱的附件一次性抓下来 → **条件必须拆成裸原子参数** `uid("SEARCH", None, "SINCE", d1, "BEFORE", d2)`，日期按 RFC 3501 不带引号；`tests/test_mailfetch.py` 守住"参数里不得出现括号或引号"。
6. **Windows 控制台默认 GBK**，打印中文/符号会 `UnicodeEncodeError` → 入口文件强制 `sys.stdout.reconfigure(encoding="utf-8")`，`.cmd` 里 `chcp 65001`；并有测试守住。
7. **`.cmd` 必须 CRLF 且纯 ASCII** → 行尾 LF 会让 cmd.exe 吞掉行首字符；已在 `.gitattributes` 固定。
8. **`Path.write_text()` 在 Windows 上会把 `\n` 变成 `\r\n`** → 写文本文件一律 `newline=""`，写完比对行数/字节数。
9. **归档根目录在仓库之外**（`D:\...\归档\`），仓库根是 `发票工具\` → 隔离靠"物理分离 + .gitignore + 启动自检 + 提交闸门"四道，不只是 .gitignore。
10. **`tempfile.mkdtemp` 建出来的目录在 DSH 沙箱下是只读的** → mkdtemp 用 `mode=0o700` 建目录，沙箱把该 mode 当成无写权限：实测 `os.stat().st_nlink == 0`，往里写文件抛 `PermissionError [WinError 5]` / `[Errno 13]`。对照实验：`os.mkdir(p, 0o777)`、`Path.mkdir()`、`Path.mkdir(parents=True)` 全都正常，唯独 `0o700` 失败 → **任何临时目录都必须用默认 mode 自己建**（见 `tests/support.py`），不要用 `mkdtemp`/`TemporaryDirectory`。
11. **系统 Temp 不在工作区内**（`C:\Users\...\AppData\Local\Temp`）→ 测试临时目录一律落在 `data/_test_tmp`（已 gitignore），否则清理阶段抛 `PermissionError`，把测试结果搞脏。
12. **Windows PowerShell 5.1 没有 BOM 时按系统 ANSI 代码页读 .ps1** → 中文参数默认值被解码成乱码，实测报 `Cannot validate argument on parameter 'TaskName'. The argument is null`，脚本直接失败 → **带中文的 .ps1 必须存成 UTF-8 带 BOM**（`EF BB BF`），并在开头设 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`，否则中文输出在捕获里也是乱码。
13. **`New-ScheduledTaskTrigger` 没有 `-Monthly` 参数** → 只有 `-Once`/`-Daily`/`-Weekly`/`-AtStartup`/`-AtLogOn` → 月度触发不能靠它。
14. **自己造 `MSFT_TaskMonthlyTrigger` 也走不通（两条路都堵死）** → 先 `-ClientOnly` 再逐属性赋值报 `The adapter cannot set the value of property "DaysOfMonth"`；构造时用 `-Property` 一次给全能建出来，但 `Register-ScheduledTask -Trigger` 报 `PSTypeNames ... do not match ... CimInstance#MSFT_TaskTrigger`，手动 `PSObject.TypeNames.Insert` 基类型名后仍失败。
15. **本机 `ScheduledTasks` 模块的写入路径整体不可用** → `Register-ScheduledTask` 无论 `-Action/-Trigger` 还是 `-Xml`（连最小 Daily XML 也一样）统一返回 `Unspecified error` `0x80004005`；`schtasks.exe /create` 更直接被拒绝启动（`Access is denied`，但 `schtasks /query` 正常）。**底层 COM `Schedule.Service` 完全可用** → 建任务必须走 COM：`New-Object -ComObject Schedule.Service` → `GetFolder('\')` → `RegisterTaskDefinition(...)`。
16. **COM 的 `IMonthlyTrigger.DaysOfMonth` 是"日期位掩码"，不是日期号** → 直接写 `20` 被解释成 `0b10100` = 第 3、5 天，注册后 `NextRunTime` 实测变成 `2026-10-03`（在它真的触发之前就发现并修正了）→ **必须设 `ITaskDefinition.XmlText`**，XML 里 `<Day>20</Day>` 才是日期号；存完读回来是 `524288 = 1 -shl 19` = 第 20 天。`register_task.ps1` 写完会回读位掩码校验，不匹配就返回非零。
17. **DSH 工具调用结束时，该调用期间启动的进程树会被清理** → 实测：用 `pwsh` 触发计划任务后立刻返回，任务里的 python 会在十几秒后被杀掉，日志只剩开头（`_open_log` 显式 flush 的那一行），看起来像"任务跑了一半就退出"；让同一次调用持续存活 150 秒再观察，任务正常跑完（`LastTaskResult=0x0`）。验证长任务时要么让调用等它跑完，要么事后看 `data/logs/*.log` 的完整度。
18. **PowerShell 的 `*>` / `Out-File` 默认写 UTF-16LE** → 命令行想留日志文件时写成 UTF-16，`read` 工具会判成 binary。要留存输出就让 Python 自己写文件，或直接看未过滤的 stdout。
19. **微信来源不能套用邮箱侧的"按基名分组"** → 桥接给入站文件的命名是 `2026-10-06_<msgid>_<idx>_<hash>.pdf`，**同一张发票的 PDF/XML/OFD 在微信侧各带一段随机串，基名根本对不上**；硬套 `mailfetch.build_groups` 会把一张发票拆成多组，造出"缺少 PDF"的假存疑（邮箱侧在携程 PDF/OFD 上踩过同类坑）→ 微信来源**只收 PDF**，OFD/XML 走"跳过留痕"，理由写清楚（见 `wechatfetch.py`）。
20. **正则不带词边界会误报** → 隐私闸门的手机号规则原本是 `1599\d{7}`，被微信消息 id `msgid0001` 里的 `1599`+7 位数命中，白报一次"真实手机号入档"。凡是"找数字串"的规则都要加 `(?<!\d)`/`(?!\d)`，否则长数字串里到处是子串。
21. **微信一条消息可能落两份同内容文件**（桥接把一张图同时存成 `.jpg` 和 `.png`）→ 实测 `assets/inbound/` 10 个文件里 3 对 md5 完全相同 → 采集时**必须按 md5 去重**，否则同一张票/图会被算两次。
22. **别把"清单"当发票** → 顺丰邮件同时带真发票 PDF 和「顺丰电子发票 — 运单明细」PDF；后者也有发票号、也有金额栏，会被当成发票并与真发票撞号，变成"重复发票不重复计入"的假存疑（2026-10 实测 3 条）→ 判据：命中「运单明细/对账单/结算单」**且正文没有「价税合计」** → 走 skipped 留痕（`extract.looks_like_document_only`）。
23. **住宿票不能单独撑起一个行程** → 某城市只有住宿票时那趟行程没有任何交通凭证支撑，硬建行程会造出"缺往返闭环"的假存疑 → 聚类要求城市组里至少有一张交通票（`TRAFFIC_KINDS`），住宿交给 `adopt_orphan_by_date` 按日期归入唯一候选。
24. **抽城市只认「销售方地址」字段** → 全文扫城市名会被开户行骗（「中国农业银行股份有限公司**成都**双楠支行」→ 成都，而酒店在遂宁）→ 用 `extract.seller_address_city`，并且要剥掉「四川省」这种省名前缀。
25. **"增量追加到同一个文件夹"和"文件夹名里带总额"互斥** → 总额一变名字就得变，所以月中生成的归档目录**不能带总额**。命名策略：月中 `{运行日}月度发票归集`；执行日 `{运行日}月度发票归集({总额})`。见 `docs/整理要求.md` §0.5。
26. **Excel 开着归档表格时 `--force` 重建会失败** → 抛 `PermissionError: [WinError 32] 另一个程序正在使用此文件`，指向 `00_发票审计明细及汇总.xlsx` → `prepare_run_dir` 现在把这条翻译成人话（"关掉 Excel 再重跑"）。调试时想绕开就先 `--out-root` 写到临时目录验证逻辑，别硬撞。
27. **Excel 的 `~$xxx.xlsx` 锁文件会被当成"手工加工过"** → 冗余目录清理的第一道保险要求"顶层条目都是工具生成的"，`~$` 前缀不属于生成物 → 于是那个目录被保留下不来，同时下次 `--force` 又删不掉。见到目录清不掉，先看里面有没有 `~$` 文件。
28. **备注是结构化的，正文不是** → 携程「代订附加」把行程写在备注：`携程订单:…,含2026-10-04 00:42成都天府国际机场接机`。这类**有固定格式的备注**可以放心正则抽城市/日期/事由；但正文里散落的城市名仍然不能扫（会被开户行骗，见第 24 条）。
29. **PDF 抽出的字段之间只有空格没有换行** → `上车点[:：]\s*(.{2,40})` 这种贪婪正则会把后半张单子全吞进来（实测"上车点"一路吞到"实际费用"）→ 每个字段都用**前瞻断言**限制在下一个字段之前：`(?=\s*(?:下车点|类型|用车时间|…))`。
30. **"城市待核"这类存疑理由不能无条件挂** → 打车票没有行程单时原来一律挂"城市待核"，可城市已经从备注认出来了；实测把两张机场接机票误判进存疑。**理由必须和判据一致**：只有当城市真的认不出时才挂。
